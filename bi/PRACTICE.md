# Практикум: собрать дашборд в интерфейсе Metabase

Основной дашборд создаёт скрипт [`setup_metabase.py`](setup_metabase.py) через API. Этот практикум — то же самое руками:
три карточки, дашборд с фильтром и публичная ссылка. Около 30 минут. Цель — уметь честно сказать на собеседовании:
«собирал кодом через API, и в интерфейсе тоже умею», и знать, какое действие в интерфейсе соответствует какой части кода.

Названия кнопок сверены с Metabase v0.64.2 на русском. В скобках — как это называется в коде.

## 0. Вход

1. Поднимите стенд, если он не запущен: `cd bi && docker compose up -d`, затем `python bi/setup_metabase.py`.
2. Откройте [localhost:3030](http://localhost:3030). Почта и пароль — в файле `bi/.env` (`MB_ADMIN_EMAIL`, `MB_ADMIN_PASSWORD`).
3. Всё, что создадите, сохраняйте в коллекцию «Наша аналитика» — коллекцию «Метрики интернет-магазина» скрипт
   пересоздаёт и ваши карточки там не нужны.

## 1. KPI «Выручка» с фильтром периода

*(в коде: `card(..., "scalar", filtered=True)`)*

1. **Новый → SQL-запрос**. База данных **Retail** выбрана сама.
2. Вставьте запрос:

   ```sql
   select sum(revenue) as "Выручка"
   from mart.orders
   where period in ('Год 1', 'Год 2')
     [[and period = {{period}}]]
   ```

   `{{period}}` — переменная, а `[[ … ]]` делает условие необязательным: без значения фильтра оно выпадает из запроса.
3. Справа откроется панель **«Переменные и параметры»**: **Тип переменной — Текст**, **Название виджета фильтра — Период**,
   **Как пользователи должны фильтровать — Поле ввода**, **Значение по умолчанию — Год 2**.
4. **Получить ответ** (или Ctrl+Enter). Должно получиться **9 330 523,44** — та же цифра, что в записке и на основном дашборде.
5. Внизу **Визуализация → Число**. Шестерёнка рядом — настройки: добавьте префикс `£`, при желании сократите до миллионов.
6. **Сохранить** → Название «Выручка (практика)» → «Куда вы хотите это сохранить?» — **Наша аналитика** → **Сохранить**.
   На вопрос про дашборд ответьте «не сейчас» — добавим всё разом в п. 4.

**Тот же KPI без SQL** (спрашивают, умеете ли вы работать в конструкторе): **Новый → Вопрос → Retail → Orders** →
**Фильтр**: Period = Год 2 → **Сводка**: Сумма по Revenue → **Визуализировать**. Результат тот же.

## 2. Выручка по месяцам по типам клиентов

*(в коде: `c["monthly"]`, display `area`, `stackable.stack_type = stacked`)*

1. **Новый → SQL-запрос**:

   ```sql
   select month as "Месяц", customer_type as "Тип клиента", sum(revenue) as "Выручка"
   from mart.orders
   where period in ('Год 1', 'Год 2')
     [[and period = {{period}}]]
   group by 1, 2
   order by 1
   ```

   Переменную `period` настройте так же, как в п. 1.3.
2. **Получить ответ** → **Визуализация → Площадь**.
3. Шестерёнка: на вкладке данных — ось X **Месяц**, серии — **Тип клиента**, значение — **Выручка**; на вкладке
   отображения включите **накопление (stacked)**. Цвета серий — по клику на цвет в легенде настроек.
4. **Сохранить** как «Выручка по месяцам (практика)».

## 3. Когорты с цветовой заливкой

*(в коде: `c["cohorts"]`, `table.column_formatting`)*

1. **Новый → SQL-запрос**:

   ```sql
   select to_char(cohort_month, 'YYYY-MM') as "Когорта",
          max(cohort_size) as "Клиентов",
          round(100 * max(retention) filter (where month_number = 1)) as "1",
          round(100 * max(retention) filter (where month_number = 2)) as "2",
          round(100 * max(retention) filter (where month_number = 3)) as "3",
          round(100 * max(retention) filter (where month_number = 6)) as "6",
          round(100 * max(retention) filter (where month_number = 12)) as "12"
   from mart.cohorts
   where cohort_month > date '2009-12-01'
   group by cohort_month
   order by cohort_month
   ```

   Почему без декабря 2009: данные начинаются с этого месяца, и в «когорту» попадает вся накопленная база, а не новые клиенты.
2. **Получить ответ** → **Визуализация → Таблица**.
3. Шестерёнка → вкладка **«Условное форматирование»** → **Добавить правило** → столбцы `1`, `2`, `3`, `6`, `12` →
   стиль **цветовой диапазон** (от белого к синему) → **Готово**.
4. **Сохранить** как «Когорты (практика)».

## 4. Дашборд и фильтр

*(в коде: `build_dashboard`, `parameters`, `parameter_mappings`)*

1. **Новый → Дашборд** → название «Практика» → Наша аналитика.
2. На панели редактирования: **Добавить вопросы** → перетащите три карточки. Растяните: KPI — узкий, график и когорты — на всю ширину.
3. **Добавить заголовок или текстовый блок** → одно предложение вывода, например: «Выручка года 2 выросла на 1,9 %,
   но постоянные клиенты покупают реже».
4. **Добавить фильтр или параметр → Текст или категория** → название **Период**. Над каждой карточкой появится список —
   выберите, к чему привязать фильтр:
   * KPI и график — переменная **Период** (`{{period}}`);
   * когорты — **не привязывать**: в этой таблице нет периода, фильтр к ней не относится.

   Значение по умолчанию — «Год 2».
5. По желанию: **Создать новую вкладку** и перенесите когорты на вкладку «Клиенты».
6. **Сохранить**. Переключите фильтр на «Год 1» — KPI станет **£9 155 346**, когорты не изменятся.

## 5. Публичная ссылка

Значок **«Доля»** (поделиться) в шапке дашборда → **Публичная ссылка**. Ссылка открывается без входа — на этом компьютере
(`localhost`); чтобы её видели другие, Metabase нужно развернуть на сервере.

## 6. Проверка себя

* Цифры на «Практике» совпадают с основным дашбордом при том же фильтре.
* Можете объяснить, чем `{{period}}` (переменная «Текст») отличается от **фильтра поля** (тип переменной для
  связи с колонкой таблицы): фильтр поля сам подставляет условие `where` и даёт выпадающий список значений из базы,
  но работает только с колонкой, к которой привязан.

## Что говорить на собеседовании

* **Как собирал:** «Дашборд описан кодом и создаётся через REST API Metabase: карточки — SQL-вопросы поверх витрин,
  фильтры привязаны к переменным запросов, раскладка и вкладки — тоже в скрипте. Пересоздаётся одной командой и лежит
  в git. Руками в интерфейсе тоже собирал — те же шаги».
* **Почему SQL, а не конструктор:** метрики (заказы без отмен, частота, доля отмен) определены в словаре метрик и в SQL
  совпадают с витринами и тестами один в один. Конструктор удобен для быстрых вопросов бизнеса без SQL.
* **Почему витрины, а не сырые данные:** 1 млн строк чеков против 47 тыс. заказов — дашборд отвечает мгновенно,
  а очистка данных сделана один раз и проверена тестами, а не в каждой карточке заново.
* **Что бы сделал в продакшне:** Metabase на сервере с SSO, ежедневное обновление витрин (Airflow, как в
  [oil-production-dwh](https://github.com/Alex91132/oil-production-dwh)), подписка на дашборд по почте,
  алерт на падение частоты у «Чемпионов».
